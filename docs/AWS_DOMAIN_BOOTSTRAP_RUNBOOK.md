# Secret Sharz AWS Bootstrap — Human Action Runbook

This document is intentionally limited to actions that require access to the AWS and Namecheap consoles. Do not paste passwords, MFA codes, access keys, secret keys or recovery codes into GitHub or chat.

## Step 1 — Create the new AWS account

Use a dedicated email address that the organisation will retain long-term.

The new account is the production parent account for the initial rebuild.

Immediately after account creation:

1. Sign in as the AWS root user.
2. Enable MFA.
3. Store recovery information securely.
4. Do not create or use root access keys.
5. Create day-to-day administrative access through AWS IAM Identity Center.
6. Use temporary credentials/roles for engineering activity.

## Step 2 — Select the primary region

Use Mumbai (`ap-south-1`) as the initial primary region.

Do not create production resources in arbitrary regions.

## Step 3 — Create Route 53 hosted zone

In AWS:
1. Open Route 53.
2. Create a public hosted zone for `secretsharz.com`.
3. Record the four Route 53 name servers.

Do not yet delete or overwrite unrelated DNS records at Namecheap.

## Step 4 — Point Namecheap to Route 53

In Namecheap:
1. Domain List -> Manage -> Nameservers.
2. Select CustomDNS.
3. Enter the Route 53 nameservers exactly.
4. Save.

Before changing nameservers, preserve any email-related MX/TXT records currently in use.

DNS propagation can take time, so verify delegation before moving application traffic.

## Step 5 — Do not issue application DNS records yet

Wait until the AWS web edge is provisioned.

Later the application will have records similar to:
- `secretsharz.com`
- `www.secretsharz.com`
- `app.secretsharz.com` (only if adopted)
- `api.secretsharz.com` (only if adopted)

Exact records will be generated by Terraform.

## Step 6 — Keep email separate

Domain registration/DNS and email are separate concerns.

Do not change MX records merely to point the website to AWS.

The account-control email, customer/support email and application emails will be handled separately.

## Step 7 — Hand back to engineering

After the following are confirmed:
- AWS account works
- root MFA is enabled
- administrative access works
- Route 53 hosted zone exists
- Namecheap points to Route 53
- domain resolves correctly

Engineering can begin Terraform bootstrap without requiring root credentials.
